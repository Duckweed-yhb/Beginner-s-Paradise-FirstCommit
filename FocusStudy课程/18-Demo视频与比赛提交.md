## 🧠 概念讲解

### 1. Demo 视频为什么重要

Presentation & Communication 占 **20%**，视频是评委了解你项目**最主要的方式**。而且"学习成长"（30%）很大程度靠视频里讲的故事体现。

**3~5 分钟的黄金结构**：

| 时间段 | 内容 | 讲什么 |
|---|---|---|
| 0:00-0:30 | 开场 | 项目名 + 解决什么问题 + 一句话简介 |
| 0:30-2:00 | 功能演示 | 任务管理 → 番茄计时 → 数据统计（录屏 + 操作） |
| 2:00-3:00 | 实现原理 | 技术栈、架构（前端/后端/存储怎么协作） |
| 3:00-4:00 | 困难与解决 | 你踩的坑、怎么 Debug（评委爱听！） |
| 4:00-4:30 | 学习与总结 | 你学到什么、下一步计划 |
| 4:30-5:00 | 结尾 | 感谢 + 部署链接 + 呼吁（"Try it!"） |

> **关键心法**：评委看的是"人"，不是"完美项目"。真诚讲你的学习过程，比炫技更打动人。

### 2. 视频脚本模板（照着填）

```markdown
【开场 0:00-0:30】
大家好，我是 XXX。这个项目叫 FocusStudy，一个帮助学生专注学习的
管理系统。它解决的是：很多同学学习没计划、不专注、不知道时间花在哪。
一句话：manage your tasks, focus with Pomodoro, and see your progress.

【功能演示 0:30-2:00】
（录屏操作，边做边说）
1. 首先看任务管理：我可以添加任务，选择科目、优先级、截止日期…
2. 然后开始一个 25 分钟的番茄专注，计时结束会自动记录…
3. 打开统计页：这是最近 7 天的专注时长，这是各科目占比…

【实现原理 2:00-3:00】
前端用 Vue3 + Element Plus，图表用 ECharts；后端是 Python FastAPI，
数据存在 JSON 文件里。前端和后端通过 API 通信……

【困难与解决 3:00-4:00】
我遇到最大的困难是……（跨域 / 定时器叠加 / 数据持久化，从学习日志里挑 2 个）
我通过……解决了，这让我学会了……

【学习与总结 4:00-5:00】
这次黑客松我学会了前端开发、后端 API、数据可视化……下一步我想加
自定义专注时长、学习提醒、多语言……

【结尾】
感谢观看！项目地址：github.com/你的用户名/focusstudy
在线体验：https://focusstudy-xxx.vercel.app
```

## 🛠 动手做

### 第一步：准备素材

1. 把 `学习日志.md` 从头读一遍——里面的"困难与解决"直接进视频
2. 准备项目截图（第 17 课已做）
3. 提前把演示流程**彩排 3 遍**（打开哪个页面、点什么、说什么，练到不卡壳）

### 第二步：录制

**工具（免费方案）**：
- **Windows 自带**：Win + G 打开 Xbox Game Bar，可录屏
- **OBS Studio**（免费开源，专业）：https://obsproject.com 下载
- 手机也可直接录屏（录制时记得打开浏览器演示部署好的线上版本）

**录制要点**：
- 分辨率 1080p 或更高，浏览器窗口最大化
- 提前关闭通知弹窗、把无关标签页关掉
- 语速放慢一点，紧张会不自觉变快
- 一个口误就重录这一段（剪辑用剪映/CapCut 免费版）

### 第三步：检查视频

- [ ] 时长 3~5 分钟（超了要剪）
- [ ] 声音清晰、无环境噪音
- [ ] 画面清晰、操作看得清
- [ ] 上传到 **YouTube**（或 B站）设置"不公开/公开"，拿到链接
  - 注意：Devpost 要求**视频链接**，YouTube 最通用

### 第四步：Devpost 提交

1. 打开比赛页面（README.md 里有链接，或搜索 "Beginner's Paradise FirstCommit devpost"）
2. 点 **Join Hackathon** → 用邮箱注册 Devpost 账号
3. 点 **Submit**（或 **Start your project**）
4. 逐项填写：

| 字段 | 内容 |
|---|---|
| Project title | FocusStudy — Student Focus Study Management System |
| Tagline（一句话简介） | A lightweight Pomodoro-based study manager with task management and learning analytics |
| Description | 用项目日记 + 第 17 课 README 的内容扩充：解决什么问题、怎么用、技术栈、学习收获 |
| Demo video | 粘贴 YouTube 链接 |
| Built With（技术栈） | Vue.js / JavaScript / Python / FastAPI / ECharts / Element Plus |
| Links | GitHub 仓库地址 + 部署地址 |
| Screenshots | 上传 3 张截图 |

5. **提交前通读一遍**，确认没有占位符、没有错别字
6. 点击提交

### 第五步：最终检查清单（提交后逐项核对）

- [ ] GitHub 仓库是 **Public**
- [ ] GitHub 有全程提交记录（第一次 commit 到最后的日期都在比赛周期内）
- [ ] README 有完整运行步骤
- [ ] 视频能打开、时长合规
- [ ] 部署链接能访问
- [ ] 项目描述里写了 **AI 使用声明**
- [ ] Devpost 页面所有必填项完整
- [ ] 截图清晰展示了三大功能

## ⚠️ 常见坑

- **坑 1**：视频超时 → 5 分钟是硬上限，超了会被拒。砍功能演示细节，保"困难与学习"部分。
- **坑 2**：临近截止才提交 → 网络/审核都可能出问题。**个人截止日：9 月 28 日**，别拖到最后一天。
- **坑 3**：视频链接权限不对（私密）→ 设成"不公开"或"公开"，并自己验证打开。
- **坑 4**：忘了 AI 使用声明 → 比赛规则明确要求，检查 Description 和 README 都写了。
- **坑 5**：时区搞错 → 截止是 **2026-10-01 05:00**（Devpost 显示的时间通常已换算成你的时区，以页面倒计时为准）。
